# SideTask 1.4.0 发布验证

## 发布内容

本次包含提交 `5a0ef6b` 的渲染性能优化、展开方式设置、动效与交互改进，以及本轮修正的列表 Enter 键误触完成问题。应用及浏览器预览版本统一为 1.4.0，继续使用 v3 数据格式。完整更新内容见 [发布说明](release-1.4.0.md)。

## 已完成检查

- 44 个 JavaScript 文件语法检查通过。
- 72 项 JavaScript 测试和 21 项 Rust 测试通过。
- 42 项浏览器界面测试通过，在 Linux Chromium 环境运行。发布前一条新增用例偶发失败：焦点停在完成按钮上按 Enter 会触发按钮默认点击而完成任务，而非打开详情；已修正为 Enter 打开任务、Space 保持完成，用例连续 6 次通过。
- Rust 格式检查通过，Windows x64 目标的 Clippy 检查通过。
- Windows x64 Release 原生构建和 NSIS 安装包生成通过，使用生产静态资源、LTO、体积优化及静态 C 运行库。
- 发布文件来自 [Windows 构建 35560455042](https://github.com/LJger/sidetask/actions/runs/35560455042)，构建提交为 `21c010d`，即标签 `v1.4.0`。工作流中的语法检查、72 项 JavaScript 测试、21 项 Rust 测试和 42 项浏览器界面测试全部通过。
- 安装版和便携版的文件及产品版本资源均为 1.4.0，SHA-256 校验文件与产物一致。
- 构建工作流中的桌面自动化通过原生启动、保存、24 组收起展开、焦点与草稿保护、并发写入、失败保存恢复和重复任务撤销检查。
- 发布前在 WSL 使用 cargo-xwin、LLVM 14 与 NSIS 3.08 交叉构建了 1.3.5 代码基线的可执行文件与安装包，确认链接与打包流程正常；该产物仅用于本地验证，不作为发布文件。

## 验证范围

构建工作流中的桌面自动化在文件对话框自动化步骤失败：测试脚本在 CI 运行器的导出对话框中未能定位文件名输入控件，与 1.3.4、1.3.5 发布时记录的问题相同，属于测试脚本对系统对话框的适配问题，不影响应用产物。该步骤之前的原生检查全部通过。

四种展开方式的真实桌面观感尚未在 Windows 实测，仅通过浏览器界面测试覆盖设置持久化与减少动态效果。真实鼠标拖动、多显示器与 DPI、Windows 10、安装升级流程以及 Edge 收藏夹和 Nexus 等程序的交互未在本轮覆盖。

升级前请保存草稿并从托盘退出旧版。
