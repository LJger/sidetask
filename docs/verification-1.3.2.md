# SideTask 1.3.2 基础验证

## 修复

针对“展开尚未完成时点击外部，再点图标无法展开”的操作，浏览器复现用例在修复前失败：预期展开，实际再次收起。

原因是自动收起途中重新获得焦点会恢复展开，紧随其后的图标点击又执行一次切换。现在图标在按下时记录展开或收起的意图，向后端发送明确的目标状态；焦点通知先于按下到达时，也能识别这次自动恢复，避免同一次点击把窗口再次收起。

排查还发现，原生拖动请求入队后，如果 Windows 没有进入移动循环，原实现会持续保留拖动锁定。现在等待系统的开始通知，500 毫秒未确认则自动释放；已经确认开始的拖动仍等待正常松手，不受这个超时影响。

保留收起图标透明度设置和 v3 数据格式。

## 基础检查结果

- 41 个 JavaScript 文件语法检查通过。
- 16 项相关 JavaScript 单元测试通过。
- 18 项 Rust 核心测试通过。新增覆盖准备阶段及动画阶段失焦、过期动画回执、失焦后未收到动画回执、未确认拖动的恢复，以及正常拖动不被超时打断。
- 10 项浏览器功能测试通过，耗时约 20 秒。重点覆盖展开中点击外部、两种焦点通知顺序、延迟的收起完成回执、再次展开及拖动；现有透明度、连点和把手可见性检查也通过。
- Windows x64 发布构建通过；安装包和便携包的文件及产品版本资源均为 1.3.2.0。安装包使用现有 Tauri NSIS 模板和生产配置生成。

焦点和回执时序在浏览器中受控模拟；拖动确认与超时在 Rust 控制器测试中验证。本轮未执行 Windows 实机操作、长期压力测试或安装升级流程，后续由用户复验。

## 用户复验

先从托盘退出旧版，再启动 1.3.2。点击数字图标展开，在动画结束前点击桌面或其他窗口，然后再次点击图标；确认能正常展开，并在收起后确认图标可拖动。也可在自动收起尚未结束时点回图标。
